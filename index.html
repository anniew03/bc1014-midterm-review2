The structure of a Java file

  • The file X.java contains one public class X. The names must match exactly, including capital letters.
  • Class names are CamelCase. Method names are lowerCamelCase.
  • Every method starts with public static.
  • The program starts running at public static void main(String[] args).
  • Compile with javac X.java, then run with java X.

Other number types from class: byte, short, long (whole numbers of different sizes), float (a less precise decimal, written 3.3F), and char (one character).

Converting between types

double q = 4; is allowed. The int becomes 4.0.

int x = 4.9; does not compile. You can't put a double into an int without a cast.

A cast drops the decimal part: (int) 4.9 is 4, and (int) -4.9 is −4.

Order of operations

*, /, and % happen before + and -.

Operators at the same level go left to right. Parentheses go first.

A condition in an if or while must be a boolean. if (1) does not compile.

Integer math

  • int / int gives an int. The decimal part is dropped, so the result rounds toward zero: 9 / 4 is 2 and -9 / 4 is −2.
  • a % b is the remainder after dividing a by b. Its sign matches a: -9 % 4 is −1.
  • + with a String on either side joins text instead of adding.
Question: Predict all eleven lines before running.
Answer
  • 2 + 3 * 4 = 2 + 12 = 14
  • 25 - 10 % 6 = 25 - 4 = 21
  • (25 - 10) % 6 = 15 % 6 = 3
  • 19 / 5 = 3, and 19 % 5 = 4, because 19 = 5 × 3 + 4
  • 5 % 19 = 5, because 19 goes into 5 zero times with 5 left over
  • -19 / 5 = −3. The exact answer is −3.8, and dropping the decimal gives −3, not −4.
  • -19 % 5 = −4, because −3 × 5 = −15, and −19 − (−15) = −4
  • 1 + 2 + "3": left to right, 1 + 2 is 3, then 3 + "3" is "33"
  • "1" + 2 + 3: "1" + 2 is "12", then "12" + 3 is "123"
  • "1" + (2 + 3): the parentheses go first, so it is "1" + 5 = "15"

doubles and overflow

Question: Predict each line. Which ones are surprising?
Answer
  • A double can't store 0.1 or 0.3 exactly, so small errors show up in 0.1 * 3 and 0.3 - 0.2.
  • 9 / 4 is 2 because both sides are ints. 9 / 4.0 is 2.25 because one side is a double.
  • double q = 9 / 4; prints 2.0. The division happens first, as ints, and gives 2. Only then is 2 turned into a double.
  • Integer.MIN_VALUE is the smallest int. Subtracting 1 wraps around to the largest int, 2147483647. This is overflow in the other direction.

&& and ||

  • a && b is true only if both are true. If a is false, Java skips b.
  • a || b is true if at least one is true. If a is true, Java skips b.
  • !a flips true and false.

  • 2 < 8 || check(3): the left side is true, so check(3) never runs.
  • 2 > 8 || check(4): the left side is false, so check(4) runs and returns true.

if and else

if (condition) {
    // runs if condition is true
}
if (condition) {
    // runs if true
} else {
    // runs if false
}
  • In an if / else if / else chain, Java runs only the first branch whose condition is true and skips the rest.
  • Separate if statements are each checked on their own, so more than one can run.
  • An else belongs to the if right before it.

Using return instead of else

Question: This version also uses separate if statements. Why does it work?
Answer

return leaves the method immediately. Once a label is returned, the if statements below it never run.

Every path must return

public static int abs(int n) {
    if (n >= 0) {
        return n;
    }
    if (n < 0) {
        return -n;
    }
}
Question: Every int is at least 0 or less than 0, so this always returns something. Why doesn't it compile?
Answer

The compiler doesn't reason about what n could be. It sees two separate if statements that might both be false, and then the method reaches the end without a return. Replacing the last if with else, or with a plain return -n;, fixes it.

while loops

while (condition) {
    // body
}
  • The condition is checked before each pass. If it is false at the start, the body runs zero times.
  • Something in the body must change a variable in the condition, or the loop never ends.
  • break leaves the loop. continue skips the rest of the body and goes back to the condition. return leaves the whole method.
Question: Which numbers are printed?
Answer

1, 2, 3, 5, 6, 7, 9. At 4 and 8, continue skips the print. At 10, break ends the loop, so 10 is not printed and 11 through 14 are never reached.

Least common multiple by adding

For a, b >= 1: start at m = a and keep adding a until m is divisible by b.

Question: Trace lcm(4, 6) and lcm(7, 3). Then edit the last line to lcm(5, 0) and run it. What happens, and why?
Answer

lcm(4, 6): m = 4, then 8, then 12. 12 is divisible by 6. Output 12.

lcm(7, 3): m = 7, then 14, then 21. Output 21.

lcm(5, 0) never ends. Remainder by zero is an error, or if you rewrite the test, adding 5 never makes a remainder of 0 against 0.

When both inputs are at least 1, each pass adds a to m, so m grows and will eventually hit a multiple of b. With a 0, that is no longer true.

Reading until −1

Read numbers one at a time until you read −1. The −1 is a stop signal, not part of the data. Count how many of the numbers are negative.

Question: What is the output for 3 -4 0 -2 8 -1? Then try 4 1 0 -1 and -1 in the input box.
Answer

3 -4 0 -2 8 -1 outputs 2: −4 and −2. Zero is not negative, and −1 is the stop signal so it is not counted.

4 1 0 -1 outputs 0.

-1 outputs 0. cur is −1 right away, so the loop body never runs.

Question: Edit the program so it also prints the smallest number it read, not counting the −1.
Answer

Add int min = cur; before the loop, but only after reading the first number. If that first number is already −1, there is no data. Inside the loop, add if (cur < min) { min = cur; }. After the loop, add System.out.println(min);. For 3 -4 0 -2 8 -1, it prints −4.

for loops

for (initialization; condition; update) {
    // body
}

The initialization runs once. Then the loop repeats three steps: check the condition, run the body, run the update. It stops when the condition is false.

Any for loop can be written as a while loop:

for (int i = 1; i <= 3; i++) {
    System.out.println(i);
}
int i = 1;
while (i <= 3) {
    System.out.println(i);
    i++;
}

A variable declared in the for initialization only exists inside the loop.

Stepping by 3

Instead of checking every number, snap to the nearest multiple of 3 at or below the input, then subtract 3 each time. The initialization is empty because j is set before the loop. The semicolons are still required.

The same start can be written with the ? : operator: condition ? valueIfTrue : valueIfFalse.

Why a loop is correct, and why it stops

An algorithm is correct if, for every input, it stops and gives the right output. For a loop you show two things:

  • Loop invariant: something that is true before the loop starts and stays true after every pass.
  • Termination measure: a positive quantity that gets smaller on every pass. Since it can't shrink forever, the loop must stop.
Question: Trace factorial(4). What is the loop invariant? What is the termination measure?
Answer

Invariant: result equals (i - 1)!, and i <= k + 1. When the loop ends, i == k + 1, so result is k!.

Termination measure: k - i + 1. It is positive whenever the body runs, and it drops by 1 each pass.

Question: Give an invariant and a termination measure for the earlier loops: product of digits, lcm, and reading until −1.
Answer
  • Product of digits: p is the product of the digits already removed from n. The measure is n.
  • lcm: m is a multiple of the original a, and no smaller positive multiple of a is divisible by b. The measure can be the gap down to the least common multiple, or you can argue that m grows by a each time and cannot pass a * b.
  • Reading until −1: count is the number of negatives among the numbers read so far. There is no variable that works as a measure. The loop stops only because the input eventually contains −1.

Practice problems

Write each one on paper first, then open the answer.

1. Fahrenheit to Celsius

Write public static int f2c(int f) that converts Fahrenheit to Celsius, rounded toward zero, using only int. The formula is C = (F − 32) × 5/9.

Question: Does (f - 32) / 9 * 5 work? Try f = 40, where the exact answer is 4.44…. And what is 212 * 5 / 9 - 32?
Answer

(f - 32) / 9 * 5 gives 0 for 40. 8 / 9 is 0, and then multiplying by 5 still gives 0. The correct answer is 4.

The fix is to multiply before dividing: (f - 32) * 5 / 9. Then 8 * 5 / 9 is 40 / 9, which is 4.

212 * 5 / 9 - 32 is 85, because you subtracted 32 at the end instead of from 212 first.

2. Days to weeks and leftover days

Write weeks(d) and leftover(d) for a number of days d >= 0. For example, 17 days is 2 weeks and 3 leftover days.

Answer

A week is 7 days. d / 7 is the weeks. d % 7 is what's left.

3. Triangle inequality

Three side lengths can make a triangle if each pair adds up to more than the third side. Write public static boolean isTriangle(int a, int b, int c) in one return statement. Check 3-4-5, 1-2-3, 2-2-5, and 5-5-5.

Answer

3-4-5 and 5-5-5 are triangles. 1-2-3 is not, because 1 + 2 is not greater than 3. 2-2-5 is not, because 2 + 2 is not greater than 5.

4. Count the digits

For n >= 0, return how many digits n has. What should 0 return? What about 1200?

Answer

0 is written with one digit, so return 1 in that case. Otherwise count how many times you can do n = n / 10 until n is 0.

1200 has 4 digits. 405 has 3. The zeros in the middle and at the end still count, because they are digits of the number.

5. Sum of the even numbers

For n >= 0, return the sum of the even numbers from 1 to n. Find evenSum(10), evenSum(1), and evenSum(4).

Answer

evenSum(10) is 30: 2 + 4 + 6 + 8 + 10. evenSum(1) is 0. evenSum(4) is 6.

6. Perfect numbers

A perfect number equals the sum of its proper divisors (every positive divisor except itself). Write public static boolean isPerfect(int n). Why can you stop the divisor loop when d * d > n?

Answer

If d divides n, then so does n / d. Once d * d > n, the partner n / d is smaller than d and has already been counted. 6 and 28 are perfect. 12 and 1 are not.

Searching and sorting

Binary search

Binary search finds a number n in a sorted list:

  1. Set lo = 1 and hi = length.
  2. If lo > hi, output false.
  3. Set mid = (lo + hi) / 2, rounded down.
  4. If list[mid] = n, output true.
  5. If list[mid] > n, set hi = mid - 1. Otherwise set lo = mid + 1. Go back to step 2.

Question: What goes wrong on an unsorted list? Can it say true when the number isn't there? Can it say false when the number is there?
Answer

It can say false when the number is there. On [8, 1, 4] searching for 8: mid = 2, and 1 < 8, so lo = 3. Then mid = 3, and 4 < 8, so lo = 4. Now lo > hi, so it outputs false, even though 8 is in the list.

It can never say true when the number isn't there, because it only outputs true after finding list[mid] = n.

Selection sort

For position 1, then 2, then 3, and so on: find the smallest number in the rest of the list and swap it into that position.

Question: Sort [8, 3, 5, 1, 7]. Write the list after each swap.
Answer
  1. Position 1: the smallest is 1. Swap 8 and 1 to get [1, 3, 5, 8, 7].
  2. Position 2: the smallest of the rest is 3, which is already there. The list stays [1, 3, 5, 8, 7].
  3. Position 3: the smallest of the rest is 5, already there. The list stays [1, 3, 5, 8, 7].
  4. Position 4: the smallest of the rest is 7. Swap 8 and 7 to get [1, 3, 5, 7, 8].

The last position doesn't need its own step. Once the first four are in place, the last number must be the largest.
